Vorschau Abschnitt 1: So funktioniert's

So funktioniert's

Der Agent bekommt nie den Token selbst, sondern nur einen eigenen Agenten-Key. Jede Nutzung läuft über Outpost — verlangt ein Eintrag eine Freigabe, fragt Outpost dich vorher.

Outpostprüft, fragt dich, setzt den Token ein

Vorschau Abschnitt 5: Gut zu wissen

Gut zu wissen

Was im Alltag auffällt.

Nur https-Remotes

SSH-Remotes (git@github.com:) gehen nicht über Outpost. Umstellen:

git remote set-url origin https://github.com/owner/repo.git
Freigabe-Karte

„Einmal“ gilt für genau diesen Zugriff, „Für diese Sitzung“ für weitere gleicher Art. Lesen und Schreiben gibst du getrennt frei.

EinmalFür diese Sitzungschreibt
IP-Bindung

„Nur von der IP dieses Servers“ lässt den Key nur von dort zu. Sieht Outpost eine andere Adresse, etwa hinter Docker oder NAT, bietet der Dialog an, sie zu übernehmen.

Entziehen

Widerruft den Key sofort und entfernt die Einrichtung auf dem Server. Fremde Zeilen in der gitconfig bleiben stehen.

SSH ohne Terminal

ssh_exec läuft ohne Terminal: interaktive Programme und sudo mit Passwortabfrage gehen nicht. Für Rechte als anderer Benutzer einen eigenen SSH-Eintrag anlegen.
